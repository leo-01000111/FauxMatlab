Install Evans

On Windows and on Apple Silicon Macs, download the standalone build: it needs nothing else installed, not even Python. Everywhere else, and wherever you want to change the code, run it from source.

Download for Windows

Windows: the installer (recommended)

  1. Open the latest release and download Evans-Setup-@@version@@.exe from its Assets list.
  2. Run it. It installs for your account only, into %LOCALAPPDATA%\Programs\Evans, so it never asks for administrator rights.
  3. Start Evans from the Start menu. Tick the box during setup if you also want a desktop shortcut.

Double-clicking an .fmdl model opens it in Evans. To upgrade, run a newer installer over the old one; to uninstall, use Apps & features. Uninstalling leaves your settings (theme, layout, recent files) in place.

Windows: the portable zip

  1. From the same latest release, download Evans-windows.zip.
  2. Unzip it anywhere, a USB stick included. Keep the folder together: the program is a folder, not a single file.
  3. Run Evans.exe inside it. Nothing is installed or registered with Windows; to remove it, delete the folder.

Both downloads hold Evans-check.exe, the same program's headless self-test. Run it from a terminal: it checks analysis results against their closed forms and builds the whole window offscreen, and its exit code is the number of failures. It exists as a separate file because a windowed program on Windows has no console to print to.

It is a one-folder build on purpose. A one-file build unpacks the whole Qt runtime on every launch, which for PySide6, SciPy and SymPy takes several seconds before the window appears.

The SmartScreen warning

The Windows build is not code-signed yet, so the first time you run it Windows SmartScreen may stop it with a blue Windows protected your PC window. That is what Windows shows for any program it has not seen signed, not a sign that something is wrong with the file.

  1. Click More info.
  2. Check that the app is Evans.exe, then click Run anyway.

Windows remembers the choice. If you would rather not run an unsigned build, run Evans from source instead: it is the same code, and you can read all of it first. The release is built by the repository's own GitHub Actions workflow from the tagged commit.

macOS: the disk image

For Macs with Apple Silicon (M1 or later) on macOS 13 Ventura or newer. To check, open the Apple menu → About This Mac: the chip should say Apple M-something. An Intel Mac, or an older macOS, can still run Evans from source, below.

  1. From the latest release, download Evans-@@version@@-macos-arm64.dmg.
  2. Open it and drag Evans onto the Applications folder beside it.
  3. Open Evans from Applications. The first time, macOS stops it; see the next section.

Double-clicking an .fmdl model opens it in Evans. To upgrade, drag a newer Evans over the old one; to uninstall, move Evans from Applications to the Bin. Updates are not automatic on a Mac yet: Evans says when there is a newer release, and you download it the same way.

The self-test is inside the app. In Terminal, run /Applications/Evans.app/Contents/MacOS/Evans --check; its exit code is the number of failures.

The “cannot be opened” warning

The Mac build is not notarised by Apple yet, so the first time you open it macOS says it could not verify that Evans is free of malware and offers only Done or Move to Bin. That is what macOS shows for any app from outside the App Store that Apple has not checked, not a sign that something is wrong with the file. Click Done, then:

  1. Open System Settings → Privacy & Security.
  2. Scroll down to the message about Evans and click Open Anyway.
  3. Confirm with your password or Touch ID, then click Open Anyway once more.

macOS remembers the choice; from then on Evans opens like any other app. (Right-click → Open, the old way round this, no longer works on current macOS.) If you are comfortable in Terminal, this does the same in one step:

xattr -dr com.apple.quarantine /Applications/Evans.app

As with Windows, if you would rather not run an unnotarised build, run Evans from source: it is the same code, and the app is built by the same GitHub Actions workflow from the tagged commit.

From source

On Windows, macOS or Linux, with Python 3.12 or newer:

git clone https://github.com/leo-01000111/evans.git
cd evans
python -m venv .venv

Activate the environment (.venv\Scripts\activate on Windows, source .venv/bin/activate elsewhere), then:

pip install -e ".[dev]"
python app.py
To…Run
check the install (headless self-test; exit code = failures)python app.py --check
run the test suitepytest -q
build the standalone app (dist/Evans/ on Windows, dist/Evans.app on macOS)pyinstaller --clean --noconfirm packaging/evans.spec

On Linux, PySide6 needs the usual Qt and X11 runtime libraries; the CI workflow (.github/workflows/ci.yml) lists the exact apt packages. There is no dependency on slycot, so a clean pip install is all it takes.

Exporting a live script as a PDF needs a TeX engine (MiKTeX, TeX Live or tectonic). Without one the report is written as HTML.
