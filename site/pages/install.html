Build from source

Windows

The installer (recommended)

  1. Open the latest release and download Evans-Setup-@@version@@.exe from its Assets list.
  2. Run it. It installs for your account only, into %LOCALAPPDATA%\Programs\Evans, so it never asks for administrator rights.
  3. Start Evans from the Start menu. Tick the box during setup if you also want a desktop shortcut.

Double-clicking an .fmdl model opens it in Evans. Evans checks for a newer release once a day and offers to update, right away or when you close it. To uninstall, use Apps & features; your settings (theme, layout, recent files) stay.

The portable zip

  1. From the same latest release, download Evans-windows.zip.
  2. Unzip it anywhere, a USB stick included. Keep the folder together: the program is a folder, not a single file.
  3. Run Evans.exe inside it. Nothing is installed or registered with Windows; to remove it, delete the folder.

Both downloads hold Evans-check.exe, the headless self-test. Run it from a terminal: it checks analysis results against their closed forms and builds the whole window offscreen, and its exit code is the number of failures. It is a separate file because a windowed program on Windows has no console to print to.

The SmartScreen warning

The Windows build is not code-signed yet, so the first time you run it SmartScreen may stop it with a blue Windows protected your PC window. That is what Windows shows for any program it has not seen signed, not a sign that something is wrong with the file.

  1. Click More info.
  2. Check that the app is Evans.exe, then click Run anyway.

Windows remembers the choice.

macOS

The disk image

For Macs with Apple Silicon (M1 or later) on macOS 13 Ventura or newer. To check, open the Apple menu → About This Mac: the chip should say Apple M-something. An Intel Mac or an older macOS can run Evans from source.

  1. From the latest release, download Evans-@@version@@-macos-arm64.dmg.
  2. Open it and drag Evans onto the Applications folder beside it.
  3. Open Evans from Applications. The first time, macOS stops it; see below.

Double-clicking an .fmdl model opens it in Evans. Evans checks for a newer release once a day and says when there is one; on a Mac you download it the same way and drag it over the old one. To uninstall, move Evans from Applications to the Bin.

The self-test is inside the app: in Terminal, /Applications/Evans.app/Contents/MacOS/Evans --check. Its exit code is the number of failures.

The “cannot be opened” warning

The Mac build is not notarised by Apple yet, so macOS stops the first launch. On macOS 15 Sequoia and newer it says Apple could not verify that Evans is free of malware; on macOS 13 and 14, that Evans can’t be opened because Apple cannot check it for malicious software. That is what macOS shows for any app from outside the App Store that Apple has not checked, not a sign that something is wrong with the file. Close the message without moving Evans to the Bin, then:

  1. Open System Settings → Privacy & Security.
  2. Scroll down to the message about Evans and click Open Anyway. It is there for about an hour after the blocked attempt; if it is gone, open Evans once more first.
  3. Confirm with your password or Touch ID, then click Open Anyway (or Open) once more.

macOS remembers the choice. On macOS 13 and 14 there is a shortcut: Control-click Evans in Applications, choose Open, then Open again; Sequoia removed it. In Terminal, this does the same on any version:

xattr -dr com.apple.quarantine /Applications/Evans.app

Linux

From source

There is no Linux build yet. Evans runs from source, below, with Python 3.12 or newer, on any distribution PySide6 supports.

PySide6 needs the usual Qt and X11 runtime libraries, even to start. On Debian or Ubuntu these are the packages the CI workflow installs:

sudo apt-get install \
  libegl1 libgl1 libopengl0 \
  libglib2.0-0 libdbus-1-3 \
  libxkbcommon-x11-0 libxcb-cursor0 \
  libxcb-icccm4 libxcb-image0 \
  libxcb-keysyms1 libxcb-randr0 \
  libxcb-render-util0 libxcb-shape0 \
  libxcb-xinerama0 libxcb-xfixes0

Most desktops have them already. There is no dependency on slycot, so after that a clean pip install is all it takes.

Why the warnings, and the alternative

Neither build is signed with a paid certificate yet, and that is all both warnings are about. If you would rather not run an unsigned build, run Evans from source: it is the same code, and you can read all of it first. Each release is built by the repository's own GitHub Actions workflow from the tagged commit, and has to pass its own self-test on Windows and on macOS before it is published.

Check your download (optional)

A checksum is a file’s fingerprint: a 64-character code worked out from every byte of it. Change one byte, by a broken download or by someone tampering with the file on the way, and the code comes out completely different. GitHub works it out for each release file when it is uploaded and publishes it beside the file; it is what the SHA-256 line under the download button shows.

To check, work out the code of the file you downloaded and compare it with that line (or with the release page). If they match, you have exactly the file the build produced.

OnRun, in the folder you downloaded to
Windows (PowerShell)Get-FileHash Evans-Setup-@@version@@.exe
macOS (Terminal)shasum -a 256 Evans-@@version@@-macos-arm64.dmg

A checksum proves the file is the one on the release page. It does not prove who built it; that is what the code signing the builds do not have yet would add.

From source

On Windows, macOS or Linux, with Python 3.12 or newer:

git clone https://github.com/leo-01000111/evans.git
cd evans
python -m venv .venv

Activate the environment (.venv\Scripts\activate on Windows, source .venv/bin/activate elsewhere), then:

pip install -e ".[dev]"
python app.py
To…Run
check the install (headless self-test; exit code = failures)python app.py --check
run the test suitepytest -q
build the standalone app (dist/Evans/ on Windows, dist/Evans.app on macOS)pyinstaller --clean --noconfirm packaging/evans.spec

The builds are one folder on purpose. A one-file build unpacks the whole Qt runtime on every launch, which for PySide6, SciPy and SymPy takes several seconds before the window appears.

Exporting a live script as a PDF needs a TeX engine: MiKTeX or TeX Live on Windows, MacTeX on a Mac, TeX Live on Linux, or tectonic anywhere. Without one the report is written as HTML.
